# HoloVLESS 1.1

This is a preview of the updated core. Old-Android runtime verification is
still required; no live phone test was available for this release.

- Update Xray-core to v26.11.9.
- Import full Xray JSON objects and arrays from subscriptions, clipboard, or
  files without discarding unknown core fields. Import remains background/batched.
- Edit JSON profiles as JSON and Hysteria2 profiles as complete share links.
- Add a main-screen Sort action: name, latency, protocol, or newest first.
- Check profiles using independent inbound-free core instances instead of
  repeatedly replacing the active VPN. Up to three tests run concurrently;
  the menu and notification can cancel them. Ping remains endpoint-only.
- Fix deleting the top/selected profile by resolving its ID rather than a
  previously bound row position. Selected-profile deletion asks for confirmation
  and stops its VPN if running.
- Bundle routing data required by full JSON profiles and retain upstream notices.

## Check behavior

The native checker follows AndroidLibXrayLite's real-delay architecture:
remove inbound listeners and routing/DNS/observatory apps from a temporary core,
then issue an HTTPS request through its default outbound using core.Dial.
Two attempts share a 12-second deadline; the best successful delay is retained.
The URL is `https://myip.wtf`; HTTP 200/204 is accepted. This verifies an outbound
connection, not every routing rule, an expected ISP, or all balancer members.
An active VPN is neither selected nor restarted for each test.

Reference: https://github.com/2dust/AndroidLibXrayLite/blob/main/libv2ray_utils.go

Full JSON is trusted core configuration, not a sandbox. Only the app bridge's
SOCKS/HTTP listeners are normalized to loopback ports 10808/10809; other JSON
fields, routing, and additional inbound protocols remain under its author's
control. Import only configurations you trust. App-generated routing preferences
do not override routing already supplied in full JSON.

## Core source and build

Xray release v26.11.9 corresponds to commit
`676eaf66f8f05d4d558ee7a74b4736623d3feeb9`, pinned in go.mod as
`v1.260327.1-0.20261109052709-676eaf66f8f0`.

Toolchain: Go 1.27.4, x/mobile
`v0.0.0-20260803200217-62cee1672c8e`, NDK 23.2.8568313, JDK 11.0.32,
Android SDK platform 30/build-tools 30.0.2, Gradle 6.7.1, AGP 4.2.2,
Kotlin 1.5.10. Set PATH, JAVA_HOME, ANDROID_HOME, ANDROID_SDK_ROOT, and
ANDROID_NDK_HOME to these installed toolchains, then run:

```sh
export GOTOOLCHAIN=go1.27.4
go install golang.org/x/mobile/cmd/gomobile@v0.0.0-20260803200217-62cee1672c8e
go install golang.org/x/mobile/cmd/gobind@v0.0.0-20260803200217-62cee1672c8e
cd AndroidLibV2rayLite
go mod download
gomobile bind -target=android/arm -androidapi 19 -ldflags=-checklinkname=0 -o ../libv2ray-api19.aar .
cp ../libv2ray-api19.aar ../V2rayNG/app/libs/libv2ray.aar
cd ../V2rayNG
bash ./gradlew clean testDebugUnitTest assembleDebug --no-daemon
```

The linker flag is needed for anet's net.zoneCache linkname with this Go
toolchain. It does not change the Android API floor or strip protocol features.
The checked-in AAR declares API 19 and contains ARMv7 only. Go's modern Android
support does not guarantee KitKat compatibility; the API-19 target is an
experimental compatibility build. Existing tun2socks binaries are unchanged.
Current module license inventory: `third_party_licenses/licenses-go-1.1/`.

## Verification

Native tests cover independent listener-free cores, direct-fallback rejection,
cancellation, socket address handling, and parsing every profile in a private
101-profile JSON fixture with the pinned routing data. The private fixture is
not included in the repository or APK. JVM tests cover JSON preservation,
batch imports, bridge normalization, Hysteria2 editing, sorting, and existing
large-import regressions. Device UI, tunnel operation, and old-Android runtime
compatibility remain unverified for the new core.

The clean build passed all 19 JVM tests with zero skips, failures, or errors,
including the private fixture. Targeted native tests passed. APK v1/v2 signatures,
packaged routing assets, and equality of the AAR/APK native library were verified.

The APK is debug-signed ARMv7, versionName 1.1; base versionCode is 216 and
the ARMv7 split's effective versionCode is 1000216. Matching source
is available in GitHub's automatic archives for the release tag; no separate
source ZIP asset is necessary.
