# HoloVLESS 1.1.1 Preview

- Replace the Sort text action with a three-line, decreasing-width sort icon.
- Remove manual drag-reordering. Long-press still opens a profile's test menu.
- Persist lightweight list metadata separately from full configurations. Normal
  list loads no longer deserialize large custom JSON documents. Old profiles
  are backfilled lazily when their group is first visited.
- Reuse Gson instances and unchanged in-memory rows rather than reconstructing
  parsers and profiles on every resume. Metadata writes/removals follow edits,
  imports, subscription replacement, and deletion.
- Display cold groups in 64-row increments and immediately reuse warm groups.
  Group-wide sort/ping/check/export actions wait until loading finishes so they
  cannot silently operate on only a partially loaded group.
- Run a bounded queue of 32 independent profile checks concurrently by default.
  As each probe finishes, its worker takes the next profile; a slow probe does
  not stall the whole next chunk. No VPN reconnection or profile selection loop.
- Add Settings > Advanced > Parallel profile checks, with limits 1/4/8/16/32/64.
  Lower the limit if an old device has insufficient memory for 32 temporary cores.
  Settings are captured in the UI process and passed to the test service so
  subsequent batches use the current value without restarting the process.

The previous HoloVLESS preview used three workers, not a single worker. The new
default is 32 as requested. Current upstream v2rayNG also uses bounded parallel
workers, though its current default is 16; this is not a claim of a byte-for-byte
port of all upstream testing behavior.

## Build and compatibility

VersionName 1.1.1, base versionCode 217 (ARMv7 split: 1000217). The core and
toolchains are unchanged from [1.1](1.1.md): Xray v26.11.9, API-19-targeted
ARMv7 AAR, JDK 11, SDK 30/build-tools 30.0.2, Gradle 6.7.1/AGP 4.2.2.
Build with the same documented clean testDebugUnitTest/assembleDebug command.
The debug APK is published separately; GitHub provides matching source archives.

The new icon has generated density-specific PNG fallbacks for pre-21 Android;
it does not require a new UI library. No dependency or SDK floor was raised.
The new core remains runtime-unverified on old Android. UI responsiveness and
32-core memory use still need device verification; no phone was available.

## Verification scope

Regression tests cover 32 simultaneous blocking workers, exactly-once scheduling
over 101 items, lower concurrency, cancellation, invalid limits, compact metadata
preservation, and edit invalidation. A native test runs 32 independent cores with
a server-side barrier requiring their requests to overlap. Existing JSON and
large-subscription tests are retained. These checks are not device benchmarks.

Final clean remote build: all 24 JVM tests passed with zero skips, failures, or
errors, including the private JSON fixture. Targeted native tests passed.
Verified APK version/signatures (v1 and v2) and pre-21 raster icon fallbacks.
